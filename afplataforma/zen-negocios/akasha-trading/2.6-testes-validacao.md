# Akasha Trading · 2.6 Critérios de testes e validação

**Status:** critérios de aceite definidos; execução de testes ainda pendente.

## 1. Princípio

A implementação só é considerada pronta quando comprova funcionamento, segurança, integridade dos dados, compatibilidade com a AF e preservação do Diário. Uma tela renderizada não é prova suficiente.

## 2. Matriz de testes

| Área | Cenário | Resultado esperado |
|---|---|---|
| Autenticação | Login e logout por e-mail/Google | Sessão correta e encerramento completo |
| Identidade | Mesmo usuário na AF e Trading | Mesmo UID, sem conta duplicada |
| Acesso | Visitante, gratuito, premium, AF, mentor e admin | Cada perfil vê apenas recursos autorizados |
| Isolamento | Usuário A tenta ler/escrever dados de B | Acesso negado no backend |
| Entitlement | Plano expirado ou pausado | Recurso premium bloqueado |
| Diário legado | Abrir, registrar, editar/excluir conforme recursos atuais | Comportamento original preservado |
| Exportação | CSV/JSON do Diário | Arquivo válido e registros completos |
| Adaptador | Ler chaves antigas | Sem mutação do localStorage |
| Importação | Importar lote válido | Contagem e campos correspondentes |
| Idempotência | Reimportar mesmo lote | Nenhuma duplicação |
| Falha parcial | Interromper rede durante import | Retomada sem perda nem duplicação |
| Integridade | Comparar origem e destino | Datas, valores, notas e ativos iguais |
| Segurança | Payload malformado/XSS | Rejeição ou escape seguro |
| Organizações | Usuário removido tenta acessar workspace | Acesso negado |
| Dados de mercado | Sem provedor ou cotação atrasada | Estado informado; sem preço fictício |
| Responsividade | Desktop, tablet e mobile | Navegação utilizável sem overflow crítico |
| Acessibilidade | Teclado, foco, rótulos e contraste | Fluxos essenciais operáveis |
| Regressão AF | Login, módulos e rotas existentes | Sem regressão nas áreas afetadas |
| Regressão Zen | Ferramentas, progresso e exportação atuais | Funcionalidades existentes preservadas |

## 3. Testes automatizados exigidos

- Unit tests para normalização, cálculos e validação de payload.
- Firebase Emulator Suite para regras de leitura/escrita e isolamento.
- Integration tests para autenticação, adaptador e importação.
- E2E para jornadas principais e níveis de acesso.
- Testes de regressão nas rotas AF, Zen Negócios, Zen Mercado e Diário.
- Verificação estática de dependências, segredos e erros de console.
- Testes de acessibilidade e viewport.

## 4. Dados de teste

Usar contas e dados sintéticos. Nunca copiar registros financeiros pessoais reais para ambientes de teste sem autorização e proteção adequada.

Conjunto mínimo do Diário:

- zero operações e zero notas;
- uma operação positiva e uma negativa;
- múltiplos ativos e direções;
- nota em cada categoria;
- campos opcionais vazios;
- caracteres especiais e acentos;
- registros em datas distintas;
- registro duplicado no lote;
- registro inválido;
- volume suficiente para paginação e limite de lote.

## 5. Critérios de aceite

A implementação não avança para produção se qualquer item crítico falhar:

1. Nenhum dado legado é perdido ou alterado sem consentimento.
2. Reimportação não duplica registros.
3. Nenhum usuário acessa dados privados de outro usuário.
4. Papéis e planos não podem ser forjados pelo frontend.
5. Fluxos de login/logout e permissões funcionam.
6. AF Plataforma e Zen Negócios não apresentam regressões.
7. Diário original permanece acessível e exportável.
8. Estados de cotações reais, atrasadas e simuladas são inequívocos.
9. Não há segredos no repositório ou bundle público.
10. Rollback foi ensaiado em ambiente de teste.

## 6. Evidências de validação

Cada release deve guardar:

- commit e versão testada;
- ambiente e data;
- testes executados e resultado;
- capturas/logs sem dados sensíveis;
- contagem de registros antes/depois da migração;
- aprovação dos critérios críticos;
- problemas conhecidos e plano de correção.

**Critério de conclusão 2.6:** checklist de aceite assinado, testes automatizados aprovados, regressão AF/Zen/Diário verificada e rollback demonstrado.
